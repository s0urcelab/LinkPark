# 数据模型

三样东西会同步：书签、标签元数据、暂存组。标签名本身不是独立实体，它出现在书签上；顺序和是否固定则记在 `tag_meta` 里，这样最后一个书签去掉某个标签之后，以后再用这个名字仍能回到原来的位置。

## 书签

| 字段 | 说明 |
| --- | --- |
| `id` | 客户端 UUID |
| `url` | 去首尾空白后原样保存，最长 8192 字符。未删除的书签里 URL 唯一 |
| `title` | 最长 1024 字符 |
| `favicon` | 文本。经操作接口写入时截断到 8192 字节；导入接口另有校验，见下文 |
| `tags` | 标签名数组。服务端存成 `tags` 与 `bookmark_tags` 两张表 |
| `rank` | 全局顺序的键，见下一节 |
| `created_at` / `updated_at` | 毫秒时间戳。创建时间非正或晚于服务端当前时间时，改记为当前时间 |
| `deleted_at` | 墓碑。增量拉取靠它告诉其他设备这条已经删除 |
| `version` | 写入时的全局版本 |

标签名会去掉控制字符和首尾空白，按 Unicode 码点截断到 64，大小写不敏感地去重，最多 32 个。空名字丢弃。

## 全局顺序

所有书签共用一条顺序，不按标签各排一份。任意标签筛选下，结果仍按这条全局顺序里的相对位置出现。

`rank` 是分数索引：字符集 `[0-9A-Za-z]`，按字节序比较，最长 128。空字符串表示还没有排过。在两个已有键之间总能再插入一个新键，因此拖拽只改被移动的那一条。键不以最低位 `0` 结尾，避免某一侧的空隙被耗尽。

批量导入用 `rankSequence` 在现有最后一项之后一次生成等间距的短键，避免逐条调用中间点把键越拼越长。

展示时 rank 不同就按字符串比较；相同则按 `created_at`，再按 `id`。

### 新书签插在哪里

新书签调用 `rankForTags`：在它携带的标签里，选当前书签数量最少、且至少已有一条的那个（最具体的一类），插到该标签最后一条的后面。没有标签，或者标签都是新的、库里还没有书签，就放到整条顺序的末尾。

从「未分类」第一次写上标签时，用同一规则重算 rank。之后再改标签，位置保持不动。

默认排序下可以拖拽。其他排序（最近添加、访问频率、名称）只影响当前列表，不改 `rank`。

名称排序用 `zh-CN` 数字感知的比较，并以汉字开头的标题排在拉丁字母和数字之后。访问频率来自浏览器历史：去掉 hash 和末尾斜杠后合并计数，平局时最近添加的在前。历史权限未授予时，这项排序没有计数可用。

筛选是「选中的标签全部命中」（且），搜索在标题、URL 和标签名里做子串匹配。

## 标签

标签栏的顺序和是否固定来自 `tag_meta`：

| 字段 | 说明 |
| --- | --- |
| `name` | 主键，`COLLATE NOCASE`。空字符串是虚拟的「未分类」 |
| `rank` | 与书签相同的分数字符串。空 rank 的真实标签排在最后 |
| `pinned` | 是否固定在标签栏 |

「未分类」在还有无标签书签时出现，默认固定，用户把它拖走之后按它自己的 rank 排。「未分类」不能重命名。

标签栏：

- 一个标签都没选时，只显示固定的标签，其余收在「更多」。
- 选中之后，只显示与当前结果有交集、且尚未选中的标签，计数是当前结果里的数量。和结果没有交集的标签不出现。

重命名会改写所有带这个标签的书签。目标名字已经存在时，两边合并，保留目标原来的顺序和固定状态。删除标签只从书签上移除这个名字，不删除书签。受影响的书签获得新版本号。`tags` 表里不再被引用的行会清掉；`tag_meta` 保留。

## 暂存

一个暂存组是一起收下的一批标签页，条目保持原来的标签顺序。

| 字段 | 说明 |
| --- | --- |
| `id` | 客户端 UUID |
| `name` | 最长 200 字符。创建时省略名字，则用来创建时间的默认名称 |
| `items` | `[{url, title}]`，服务端以 JSON 文本存储，一组最多 1000 条 |
| `created_at` | 列表按创建时间从新到旧 |

暂存当前窗口需要 `tabs` 权限，首次使用时申请。可以整组打开、逐条收成书签，或从组里移除。

## 导入

导入把浏览器书签树或 Netscape HTML 展平，一次性 `POST /api/v1/import`。

- 深度优先遍历。一条书签路径上的每一级文件夹都成为一个扁平标签。看不见的根，以及它的直接子节点（「书签栏」「其他书签」等）不计入路径。这些容器根下的散落链接没有标签，归入「未分类」。
- 书签栏上的文件夹对应的标签默认固定。
- 全局顺序就是这棵树的深度优先顺序。rank 在发送前、接在已有书签之后生成。
- 很旧的书签可能没有 `dateAdded`。它借用前一个兄弟的时间，再没有则用所在文件夹的时间，避免被记成「现在」后跑到「最近添加」的最上面。服务端能接受的最早时间戳是 1。
- 勾选「放入暂存区」的文件夹不导入为书签。该文件夹（含子文件夹）下的链接按原顺序进入一个暂存组，组名是文件夹名。超过 1000 条时拆成带序号的多组。
- 同一批里重复的 URL 合并：标签取并集，保留第一份可用的 favicon，重复的条数计入 `skipped`。库里已有的 URL 跳过。
- 随导入提交的标签元数据只在该标签还没有元数据时写入，不会覆盖用户已经排好的顺序和固定状态。

网站图标在导入时保存为 data URL。只接受 `png`、`jpeg`、`gif`、`webp`、`x-icon` 的 base64 data URL，超过 64KB 或格式不对就丢掉，书签仍然导入。浏览器缓存里的图标和 HTML 文件里带的图标都会收集。展示时，若 Chrome 对这个地址给出的是默认地球仪，就用当时存下的那份；本机后来缓存到真实图标，则显示新的。

导入接口单次最多 5000 条书签、5000 条标签元数据，请求体上限 16MB。文件夹名不合规时尽量截断后保留，不因为一个名字拒绝整条书签。
