# 同步

写操作先改本地，再排队发给服务端。服务端在一个事务里整批接受或整批拒绝。客户端随后按版本号把变化拉回来，多台设备以服务端已经提交的结果为准。

## 一次修改怎么走

1. 界面或右键菜单构造一条操作：`op_id`、`entity`、`type`、`id`、`payload`、`client_ts`。`op_id` 和实体 `id` 都是客户端生成的 UUID。标签操作的 `id` 是标签名，空字符串表示虚拟的「未分类」。
2. `applyOp` 立刻把这条操作反映到本地视图，同时把它追加到 outbox。
3. Service Worker 用 300ms 防抖把连续编辑合成一次同步。
4. 同步引擎每次最多取 outbox 前 200 条，`POST /api/v1/ops`。服务端单批上限是 500。
5. 推送成功后、从 outbox 删除之前，先 `GET /api/v1/bookmarks?since=<cache.version>`。这样乐观更新不会在「本地已删、拉取尚未写回」的空隙里闪一下。
6. 拉取结果写进 cache，已发送的 `op_id` 从 outbox 去掉。outbox 里还有剩余时立刻再跑一轮。

引擎是单飞的：同步进行中又有新的调用，只会在本轮结束后再跑一次。对 storage 的读改写套在同一把异步锁里，锁不能嵌套。

## 服务端如何应用一批操作

`ApplyOps` 开一个事务。每一条操作：

- `op_id` 已在 `applied_ops` 里：记为 `replayed`，不改数据。
- 否则按实体分发。校验失败（非法 JSON、非法 rank、标签过长等）时整个事务回滚，这一批都不会留下。
- 成功、跳过或忽略之后，把 `op_id` 写入 `applied_ops`。

每次真正写入都会把全局版本加一，被改的那一行记下当时的版本。同一批里的多条写入因此带着递增的版本号；响应里的 `version` 是整批提交之后的值。`replayed` 和创建时的 `duplicate` 不推进版本。删除即使目标已经不存在，也会写下墓碑并推进版本，用来挡住后到的、同一个 `id` 的创建。

进程每 24 小时删除 30 天以前的 `applied_ops`。在这之后同一 `op_id` 再出现会被当成新操作。

每条操作的结果：

| 状态 | 含义 |
| --- | --- |
| `applied` | 已写入 |
| `duplicate` | 创建或改 URL 时，未删除的书签里已经有这个地址，本条跳过 |
| `ignored` | 目标不存在、已经删除，或创建撞上了更早的删除墓碑 |
| `replayed` | 这个 `op_id` 以前处理过 |

删除一个尚不存在的书签仍会留下墓碑。后到的、同一个 `id` 的创建不会把它复活。

## 增量拉取

`since <= 0` 表示全量：只返回未删除的书签和暂存，`full` 为 true。`since > 0` 时返回 `version` 更大的行，包括 `deleted_at` 有值的墓碑。标签元数据没有墓碑，每次都给完整列表 `[{name, rank, pinned}]`。

客户端合并时，全量用拉取结果替换整张表；增量则按 id 覆盖，遇到墓碑就删掉本地行。标签表每次都整表替换。

若服务端当前版本比本地缓存的版本更小（例如数据库被换掉或还原），客户端丢掉增量结果，改用 `since=0` 重新拉全量。

## 失败与重试

| 情况 | 处理 |
| --- | --- |
| 401 / 403 | 状态改为 `auth_error`，停止重试。改 Token 或显式全量同步之后才会再试 |
| 推送阶段的其他 4xx | 这一批从 outbox 挪到 `failed`。自动重试只会再次失败。用户可以重试或丢弃 |
| 网络错误、超时、408、429、5xx，以及拉取失败 | 留在 outbox。退避 1s、2s、4s……上限 5 分钟，用 `chrome.alarms` 叫醒 Service Worker |

请求超时 20 秒。另外每 30 分钟、浏览器启动、网络从离线恢复、以及 Service Worker 醒来时发现 outbox 非空，都会再同步一次。

`failed` 里的批次重试时插回 outbox 头部，保证原先的先后关系。

服务端地址变更时会清空 cache（版本归零）再做一次全量拉取。只改 Token 则保留缓存，直接全量拉取。两种情况下，outbox 里尚未确认的操作都会继续推送。

## 多设备

服务端按到达顺序应用补丁，同一字段后写入的值留下。客户端不做字段级合并：拉取到的行覆盖缓存，本地还没确认的 outbox 再叠上去。

两台设备可能为同一次插入生成相同的 rank。比较时 rank 相同则按 `created_at`，再按 `id`。生成 rank 时如果下界已经不小于上界，就改成排在下界之后，而不是失败。

创建书签时若服务端已有同一 URL，返回 `duplicate`。扩展只对书签创建统计这个状态，并在同步完成后提示跳过了几条。
